设计圈最近在聊一个让人有点不适的问题：你辛苦设计的界面，下一个"用户"可能根本不是人。

不是比喻。

四月初，有两件事同时发生。Tubi（Fox 旗下的免费流媒体）把自己的服务装进了 ChatGPT，用户不用离开对话框就能搜索和播放视频。几乎同一天，一家叫 Astropad 的公司发布了新产品 Workbench——一个专门给 AI agent 用的远程桌面。它的目标用户不是运维工程师，是 Claude 和 GPT 这样的 AI。

这两件事指向同一个方向：**产品的使用者，正在从人类变成 AI。**

---

## 这到底意味着什么

过去做产品设计，假设一个有眼睛、有判断力、会在界面上犹豫的真实用户。按钮得清楚，颜色得对，反馈要即时——因为人类会搞混，会分神，会放弃。

现在有了另一种用户：AI agent。

它不需要漂亮的界面。它需要的是清晰的规则——能做什么、不能做什么、出错了怎么处理。它不看颜色，不受排版影响，也不会因为"体验好"而多用一次。

所以设计问题从"这个界面好不好用"变成了"这个工具能不能被 AI 理解和调用"。

Astropad 的案例很说明问题。他们原来做 iPad 绘图配件，产品一直卖给设计师。但他们观察到用户开始在 Mac Mini 上挂着 AI agent 跑长任务——分析数据、做报告、处理文件——然后时不时需要人类介入看一眼发生了什么。原来的远程桌面软件设计给工程师的，界面复杂。Workbench 的重新设计做了减法：高清显示日志、快速审批 agent 的决策、多台 Mac 之间的快速切换。

服务的不是工程师，是盯着 agent 的人类操作者。UI 的复杂度反而下降了。

---

## 谁在做，怎么做

不只 Astropad。

**Slack** 去年推出了 Agent-Ready API，让开发者可以在 Slack 里建 AI agent。你在频道里 @它，它可以启动任务、调取对话历史、在 Slack 内输出结果。它理解 Slack 的对话语法，也理解人类的语言——两套逻辑要同时跑。

**Atlassian 的 Confluence** 现在可以接入 Lovable、Replit、Gamma 这些 AI 工具作为 agent。文档工具里长出了生成和执行能力。

**Anthropic** 主导推出了 MCP（Model Context Protocol），这是一个正在成为行业标准的协议，定义了 AI agent 如何调用外部工具和服务。现在大量产品都在给自己的功能加上 MCP 接口，为的就是让 AI agent 能直接调用，不需要人类在中间点按钮。OpenAI、Google 等也有类似支持，但 MCP 是 Anthropic 主导的。

还有 Poke，一个让普通用户通过发短信就能触发 AI agent 的产品。入口极度简化，但也因此失去了深度——这条路大概率走不长，但它反映了同一个趋势：agent 正在成为用户和产品之间的中间层。

---

## 对设计师意味着什么

以前说"设计体验"，指的是人类使用时的感受。

现在这个定义在扩展：**体验也包括 AI agent 能不能顺畅地用这个产品完成任务。**

有几件事会变：

一是**你需要想清楚谁在用**。同一个功能可能有两类使用者：人类用户（通过界面操作）和 AI agent（通过程序调用）。两者的需求可能不一样。人类需要引导和反馈，agent 需要规则和精度。

二是**"易用"的定义变了**。对人类，易用意味着直觉、熟悉感、少思考。对 agent，易用意味着清晰、可预测、错误有回路。以前只考虑前者就够了，现在两个都要考虑。

三是**设计的边界在扩大**。你不只在设计界面，也在参与决定这个产品怎么被 AI 系统理解。这意味着设计师需要和工程团队更早、更深度地合作，甚至要开始关心产品的接口设计——不是写代码，而是参与决策它应该暴露什么能力、允许什么操作。

## An 需要想的问题

你现在在做 Image Creator 和 Video Creator。这两个产品很快就会面临一个选择：**要不要让 AI agent 来调用它？**

想象一个不太远的场景：用户告诉 Copilot "帮我做一套节日宣传图，五张，风格要现代简洁"，Copilot 直接调用 Image Creator 生成结果，不需要用户点进另一个界面。这不是假设，这是 Copilot 的演进方向。

如果 Image Creator 能被 agent 调用，意味着：用户的触达路径多了一条，每次 Copilot 帮用户做内容创作的时候，它都可以顺手用上。量级完全不一样。

要做到这件事，不只是工程的工作。你作为产品设计师需要想：
- 用户有多少种"生成图片"的意图？这些意图怎么被 agent 理解？
- Image Creator 的"风格"选项，能不能用语言描述，而不只是视觉选择器？
- 如果 agent 生成失败，用户应该知道什么、能做什么？

这些是设计问题，不是工程问题。

---

## 最后说一句

Human-centered design 没有过时。它的核心是：从使用者的需求出发，而不是从技术出发。

Agent-first 不是抛弃这个原则，而是扩展了"使用者"的定义。

现在的产品，越来越多会被 AI 系统调用、被 AI 流程嵌入、被 AI 决策影响。会设计"人能用"的产品还不够——会设计"AI 也能用"的产品，才是下一阶段的竞争力。

这个趋势不是五年后的事，它已经在发生了。
