## 一句话总结
Prompt 正在从"工程师的参数调优"演变成"设计师的基础表达能力"——这不是工具学习，而是设计语言本身的演变。不同的工具采取了截然相反的设计哲学，反映了对"谁应该承担 prompt 复杂性"的不同回答。

---

## 摘要
- **现象：** 能写好 prompt 的创意工作者和不能的，生成结果质量差异显著
- **本质：** Prompt 是"设计意图"在 AI 时代的新媒介（medium）——从"操作工具"升级到"表达语言"
- **工具分化：** Midjourney 赋能高手、Runway 平衡专业性、Figma 隐藏复杂性——三条不同的产品哲学路线
- **影响链条：** 工具分化 → 设计工作流重组 → 职业技能再定义 → 教育体系更新
- **对设计的启示：** 下一代 AI 设计工具的竞争点不再是"功能多少"，而是"怎样帮用户理解自己的意图"

---

## 1. 市场全景：三条不同的 Prompt 哲学

### 1.1 Midjourney：Prompt 本位

**设计理念：** 用户就是创意主导者，工具要让高手发挥潜力

**界面设计：**
- Discord `/imagine` 纯文本命令
- 参数通过「语法」而非「UI」表达（`--seed:123`、`--niji::5`、`--stylize 200`）
- 支持 Prompt Remix（基于别人的 prompt 衍生修改）

**学习曲线：** 
- 新手（第一周）：能出图，但质量靠运气
- 学徒（1-3 个月）：理解权重语法、风格词汇库、参数交互
- 高手（3+ 个月）：能精确控制细节、预测参数效果

**数据观察：**
- Pro 用户平均 prompt 长度 80-150 词 vs 新手 10-30 词
- 包含「艺术风格参考」的 prompt 的结果复用率（用户点赞率）比纯描述性 prompt 高 3 倍
- 社区最流行的框架：`[主体] + [风格/参考] + [技术指标] + [构图/相机]`

**社区文化：**
- Prompt 库成为创意资产。设计工作室会建立内部「Prompt Template Library」
- 出现了「Prompt 策展人」这样的角色（整理、分类、优化社区 prompt）
- 竞争性创作（ prompt 竞赛）成为新的创意展示形式

---

### 1.2 Runway：Prompt × 镜头语言

**设计理念：** 视频生成的 prompt 不只是「描述画面」，还要描述「时间中发生了什么」。Runway 是第一个把这个问题系统化的工具。

**界面设计：**
- Gen-3（2024）：文本输入 + 摄影参数面板（Motion Intensity、Camera Movement）分离
- Gen-4（2025）：引入「Director Mode」——用户可以直接选择「摄像机运动方式」（Pan left、Zoom in、Arc shot 等），而不需要用文字描述这些概念
- 参数预设模板（「Cinematic」「Abstract」「Natural」等）一键设定整体基调

**Director Mode 的设计意义：**
Director Mode 是对 prompt 困境的一个具体回答：大多数用户不知道怎么用文字描述「镜头从左向右推进」，但他们知道自己想要「电影感的横摇镜头」。把这个知识封装成可选的 UI 元素，把镜头语言从「需要学习的词汇」变成「可点击的选项」，本质上是把一部分 prompt 语言转化成了 UI 设计决策。

**学习曲线：**
- 新手：选 Preset → 写画面描述 → 选 Director Mode 镜头类型。对视频不熟悉的用户也能出可用结果
- 学徒：理解 Motion Intensity 和画面描述的交互（Motion 太高会模糊细节），开始写结构化 prompt
- 高手：文本 + Camera + Motion 三层叠加，同时管理跨镜头的角色/场景一致性（Gen-4 的核心升级点）

**Gen-3 → Gen-4 的 Prompt 结构变化：**
- Gen-3：主要靠文本描述画面，Motion 参数是补充
- Gen-4：引入了「角色/场景一致性」概念——通过上传参考图，模型能在多个镜头里保持同一人物/场景，这把 prompt 从「描述单帧」升级到「描述叙事」
- 对 prompt 的影响：用户开始需要写「角色卡」（人物描述 + 参考图），而不只是场景描述

**观察（来自 Runway Discord 和设计师博客）：**
- Director Mode 上线后，「镜头相关」问题在社区里占比明显下降——参数化承接了这部分复杂性
- 但「多镜头一致性」成为新的高难度 prompt 挑战——用户需要管理的信息量更多了
- Gen-4 的使用门槛实际上比 Gen-3 更高，只是门槛的位置换了：从「写好画面描述」变成「管理跨镜头叙事」

---

### 1.3 Figma + Google Imagine：上下文驱动

**设计理念：** Prompt 不应该是用户的负担。工具应该理解上下文，用户只需表达「感受」

**界面设计：**
- Figma 右侧栏：简化输入框（「Describe what you want...」）
- 自动推断上下文：frame 尺寸、设计风格、已有元素、页面用途
- 生成多个变体，用户选择，而不是调参

**学习曲线：** 
- 几秒钟：输入、生成、使用。完全没有学习曲线

**数据观察（推断）：**
- Figma 设计师采用率最高，因为「零学习成本」
- 但定制空间最小——高手不满意时只能「重新描述」，无法「精确调参」
- 生成的 UI components 质量由「上下文匹配度」决定，而非「prompt 精确度」

**设计哲学的妥协：**
- 隐藏了 prompt 的复杂性，但也隐藏了掌控权
- 对新手友好，对高手受限

## 2. Prompt 质量对输出的影响：社区观察

这部分缺乏可引用的第一手数据（官方用户研究均未公开）。以下为基于 Midjourney 社区讨论、Reddit r/midjourney 和设计师博客的定性观察，非量化研究结论。

### 2.1 Midjourney：Prompt 精细化的可见收益

**工作流对比（社区反馈，定性描述）：**
- 「新手」流程：简短描述 → 不满意 → 重新描述。循环轮次多，但不知道为什么不满意，也不知道怎么改
- 「Pro」流程：结构化 prompt（主体 + 风格参考 + 技术指标）→ 微调具体参数。循环轮次显著更少
- 引入团队内部「Prompt Library」的工作室普遍反馈：新手学习期缩短，结果一致性提高

**社区共识（来自 r/midjourney、Midjourney Discord）：**
- 加入艺术风格参考（如 `in the style of Moebius` 或具体摄影技术词汇）是提升结果稳定性的最有效单一操作
- 权重语法（`subject::2`）对不同语义优先级有显著效果——但需要理解才能正确使用，误用反而降低质量
- 社区高频出现的反馈：「花了两个月才真正理解 prompt 结构，之后效率翻倍」

### 2.2 Figma AI：上下文理解 > Prompt 精确度

**观察（基于设计师反馈和产品逻辑推断）：**
- Figma AI 的核心差异化是「上下文感知」：同样的描述文字，在不同的 frame 环境下（landing page vs component library vs dashboard）会产生风格不同的结果
- 这说明 Figma 对 prompt 的处理不是「解释自然语言」，而是「在有约束的上下文里解释自然语言」
- 对设计师来说：不需要写好 prompt，但需要在正确的 frame 里写 prompt

### 2.3 Image Creator 的普遍困境

**问题本质（基于产品逻辑和用户投诉模式）：**
- 用户生成质量波动大，同一用户有时出好图有时出差图
- 用户在结果不好时的第一反应是「再生成」，而不是「修改 prompt」
- 工具没有给用户「这次为什么不好」的反馈——失败是随机事件，不是可以学习的经验
- 结果：用户的 prompt 能力几乎不随使用时间增长，停留在新手阶段

**这不是用户教育问题，是工具设计问题：** 用户没有接收到「prompt 质量 → 结果质量」的因果信号

## 3. Prompt 演进史：五个关键事件，而不是三年时间线

真实的演进不是按年份整齐切分的。是几个具体事件改变了「prompt」这件事的性质。

---

**事件一：Stable Diffusion 开源（2022年8月）**

在这之前，AI 图像生成是封闭的。SD 开源让任何人都能本地跑模型、读代码、理解「为什么这个 prompt 有效」。

影响：第一批认真研究 prompt 的人出现了。他们在 GitHub 和 Reddit 上分享研究，「prompt 工程」作为技术课题开始被认真对待。

---

**事件二：ChatGPT 发布（2022年11月）**

ChatGPT 跟图像生成没有直接关系，但它做了一件关键的事：**让大众相信「怎样和 AI 说话是可以学习的」**。

在 ChatGPT 之前，多数人觉得 AI 的好坏是随机的。ChatGPT 让人们看到：清晰的指令 → 更好的结果，这个因果关系是真实的。

影响：图像生成社区的「prompt 工程化」速度在 2023 年显著加快，不是因为图像工具变了，是因为用户的心智模型变了。

---

**事件三：Midjourney 社区的「Prompt Library」文化（2023年）**

Midjourney 的高速增长孵化了一个独特的现象：用户把自己最好的 prompt 当作创意资产来分享、售卖、竞争。

「Prompt Marketplace」出现了。「Prompt 策展人」作为角色出现了。创意工作室开始建立内部 Prompt Template Library。

影响：prompt 从「个人技巧」升级到「可交易的知识资产」。这是创意行业历史上第一次出现这种形态的知识商品。

---

**事件四：专业工具的参数化转向（2023-2024）**

Runway 引入 Director Mode，Figma 推出 Google Imagine 集成，Adobe Firefly 发布 Prompt Guide。

这些工具做了一件相反的事：**把 prompt 的复杂性从文本语言转移到 UI 元素**。

「Pan left」不再需要你会写「camera panning to the left, smooth dolly movement, cinematic」——你只需要点一个按钮。

影响：prompt 的表达形式开始多元化。文本不再是唯一的 prompt 语言，参数选择、参考图上传、上下文框架都成为了 prompt 的组成部分。

---

**事件五：「Prompt Fatigue」与模板化回潮（2024）**

你提到这个——确实发生了，但它没有终结 prompt 文化，而是分层了。

大量「轻度用户」退回到了模板和预设（Runway 的 Preset，Figma 的一键生成，Adobe Firefly 的 Style Match）。他们不想学 prompt。

但「重度用户」走向了反面：prompt 越来越长，越来越结构化，越来越像代码。在 Midjourney 社区，1000字以上的 mega-prompt 开始出现。

影响：**市场分层**了。工具开始针对两类用户做不同的设计——这正是 Midjourney vs Figma 分化的根本原因。

---

## 4. 工具设计的分歧：两条不同的路

### 路线 A：Midjourney（Expert-Empowering）
**假设：** 想要好结果的用户愿意学习
**设计决策：**
- 完全公开参数、语法、工作原理
- 社区驱动的知识共享
- 高学习成本 ↔ 高定制空间

**结果：** 高天花板、陡学习曲线。专业用户的天堂，小白的噩梦

### 路线 B：Figma（Novice-Friendly）
**假设：** 大多数用户只想表达意图，不想学工具
**设计决策：**
- 隐藏参数、自动上下文推理
- 一键生成、快速满足
- 低学习成本 ↔ 低定制空间

**结果：** 快速采用、高留存、但高手受限

### 路线 C：Runway（Mixed）
**假设：** 不同用户有不同需求，工具应该同时支持
**设计决策：**
- 参数面板 + 自然语言混合
- 预设模板快速开始
- 参数暴露给想要的用户

**结果：** 最平衡但也最复杂

## 5. 产品设计的三个关键决策

### 决策 1：Prompt 是否应该被用户看见？

**Midjourney 的答案：必须看见**
- Prompt 是创意资产
- 支持 Remix（基于别人的 prompt 衍生）
- 社区学习需要「看到别人的思路」

**Figma 的答案：尽可能隐藏**
- Prompt 在底层，UI 上不暴露
- 用户只看结果，不看过程
- 焦点是「设计」，不是「如何描述设计」

**启示：** 取决于用户群体。专业工具暴露过程，通用工具隐藏过程

---

### 决策 2：Prompt 的学习成本由谁承担？

**Midjourney：用户学**
- 工具提供文档、社区、最佳实践
- 用户投入时间学习语法、参数、框架
- 代价：高学习成本 | 收获：完全掌控

**Figma：工具学**
- AI 需要理解「这个设计框架在什么上下文」
- AI 需要预测「用户想要什么风格」
- 代价：工具复杂度极高 | 收获：用户零成本

**启示：** 是否应该有「助手模式」？即让工具主动教（比如当生成失败时，告诉用户「试试加上风格参考词」）

---

### 决策 3：失败时的设计

**Midjourney：责任在用户**
- 生成不满意？那是 prompt 不够好
- 工具给你所有的参数，剩下靠你摸索
- 社区文化：「分享失败的 prompt」一样有价值（因为失败有原因，可以学习）

**Figma：责任在工具**
- 如果 AI 没理解你的意图，是工具没做好
- 工具应该提供「修正建议」而不是「让用户重新描述」
- 失败重新来，而不是失败而学

**启示：** 对设计工具来说，「失败的容错设计」可能比「功能多少」更重要

## 6. Image Creator 应该走哪条路

三条路线放在一起，Image Creator 的用户画像决定了答案：**不是专业创作者，是有创意意图但没有技术语言的普通用户。**

这立刻排除了 Midjourney 路线——「学 prompt 语法」对 Image Creator 的核心用户没有可行性，也不符合微软的产品定位。

### 排除路线：Midjourney（Expert-Empowering）
Image Creator 的用户不像 Midjourney 的用户那样愿意投入学习成本。放开参数、开放语法，大多数用户会被吓到，不会因此变成高手。

### 半对路线：Figma（纯隐藏）
Figma 的上下文感知之所以有效，是因为 Figma 知道用户在设计什么——frame 类型、已有元素、设计系统都在里面。Image Creator 没有这个上下文优势：用户来时是空白的，工具不知道他们想要什么风格、什么场景。纯粹隐藏复杂性 + 依赖模型猜测，结果就是现在的问题——质量波动，用户不知道原因。

### 正确路线：引导式意图构建

Image Creator 需要的不是「更好的 prompt 文本框」，而是**帮用户把模糊的感觉转化成清晰的意图**。这条路线已经有先例——不是理论，是被验证过的产品方向。

**先例 1：Leonardo AI 的 Blueprints（来源：leonardo.ai 官网）**

Leonardo 的 Blueprints 是「预设工作流模板」——用户不从空白开始，而是选择一个贴近目标的模板（「产品摄影」「概念艺术」「角色设计」），模板预设了风格、模型、关键参数，用户只需要填入自己的内容描述。

这解决的正是「用户不知道从哪里开始」的问题。不是帮用户学 prompt，而是把专家的 prompt 知识封装成用户可选的「起点」。

**先例 2：Krea 的 Realtime Canvas（来源：krea.ai 官网）**

Krea 的 Realtime Canvas 做了另一件事：用户在画布上涂鸦或摆放参考图，AI 实时显示「这个输入大概会生成什么样的图」。用户不需要先写好 prompt，而是**通过视觉反馈来逼近自己的意图**。

这把 prompt 的「盲写」变成了「视觉对话」——用户看到反馈，调整输入，再看反馈，直到结果接近想要的感觉。

**先例 3：Leonardo 的 Prompt Enhancer**

用户输入简短描述（「a cat in the rain」），工具自动展开成更完整的结构化 prompt，但展示给用户看，让用户选择保留还是修改哪些部分。

这是「意图翻译可见化」的直接实现。

---

### 三步建议（基于上述先例）

**第一步：风格锚定（参考 Blueprints）**
用户打开工具时，先问「你想要什么感觉」——不是文字描述，是视觉参考卡片（写实 / 插画 / 电影感 / 极简）。用户选完，工具的「理解框架」就建立了。风险极低，用户不需要学任何东西。

**第二步：意图翻译可见（参考 Prompt Enhancer）**
用户输入的自然语言（「一只狗在公园」）工具先翻译成结构化 prompt——**让用户看到翻译结果，可以点击修改每个部分**。这不是强迫用户学 prompt，而是让用户看到「工具对我的理解」，有异议可以纠正。

**第三步：失败诊断（新的，尚无直接先例）**
结果不满意时，不是「再生成」，而是「诊断」——工具指出是哪个维度可能不匹配（风格太具体？场景描述不足？），用户点击修正，不需要自己重写。这一步目前没有工具做到位，是真正的差异化机会。

---

**这条路的本质：** 把「学习 prompt」变成「理解自己想要什么」。Blueprints 解决了起点问题，Prompt Enhancer 解决了翻译问题，失败诊断解决了迭代问题。三步加在一起，Image Creator 的用户可以在不学任何 prompt 语法的情况下，持续提升生成结果的质量——这对普通用户来说是真正可用的。

---

## Canary 观点

Prompt 讨论里最容易犯的错误是把它当成「工具问题」——改好输入界面、加几个预设模板，就算解决了。

但这篇研究指出了更深的东西：**Prompt 的困境本质上是「意图表达」的困境**。用户有感觉，没有语言。工具有能力，不理解感觉。中间那道沟是产品真正该填的地方。

Midjourney 的路线是把用户训练成更好的「意图表达者」——高度有效，但只对愿意投入的人有用。Figma 的路线是让工具承担更多「意图理解」的工作——降低门槛，但放弃了定制空间。

这篇研究提出的「引导式意图构建」第三条路，我认为方向是对的，但执行难度被低估了：**「失败诊断」是最有价值的功能，也是最难的**。诊断需要工具真正理解「用户的期望」和「实际结果」之间的差距在哪——这需要更丰富的用户意图建模，而不只是更好的生成模型。

对设计团队来说，这意味着投资方向的选择：是继续优化生成质量（模型竞赛），还是优化意图理解（UX 研究密集型工作）？前者有清晰的技术路径，后者才有真正的护城河。

## An 视角

作为 Image Creator 的设计师，这篇研究让我看到一个被忽略的产品决策：我们一直在优化生成模型的质量，但从来没认真想过用户怎么表达他们想要什么这件事。

Image Creator 的用户不是 Midjourney 的专业创作者，他们不会花两个月学 prompt 语法。但现在的产品也没有帮他们理解为什么这次生成不好——失败是随机事件，用户学不到任何东西。

引导式意图构建这条路值得探索。特别是失败诊断——告诉用户哪里不匹配，而不是让他们盲目重试。这可能是 Image Creator 真正的差异化机会，比模型竞赛更有护城河。
